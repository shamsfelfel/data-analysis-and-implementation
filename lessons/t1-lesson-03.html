The problemالمشكلة

Whatever file or API reply you load reaches Python inside a container before it ever becomes a table. For 60 rental listings the obvious container is a list with one dictionary per listing, and it works right up to the moment you ask it to do arithmetic across rows, to sort by rent, or to cope with a blank cell. Each of those three failures is quiet, or shows up far from its cause.

أيًّا كان الملف أو ردّ الواجهة البرمجية الذي تحمّله، فإنه يصل إلى بايثون داخل حاوية قبل أن يصير جدولًا. وللإعلانات الستين تكون الحاوية البديهية قائمةً فيها قاموس لكل إعلان، وتعمل جيدًا حتى اللحظة التي تطلب منها حسابًا عبر الصفوف أو الترتيب بالإيجار أو التعامل مع خلية فارغة. وكل واحد من هذه الإخفاقات الثلاثة صامت، أو يظهر بعيدًا عن سببه.

AI lensمنظور الذكاء الاصطناعي

A model eats a numeric matrix, never a list of dictionaries of strings. Whatever sits between the file and that matrix is your responsibility, so convert once, in one place, and make the conversion visible. A feature such as "rank of the rent" computed on text ranks '99' above '415' and nobody notices, because the column still looks like rents. And the quick fix float(x or 0) manufactures a training row whose rent is zero for 2 of the 60 listings: a made-up label, not a missing one.

يتغذّى النموذج على مصفوفة رقمية، لا على قائمة قواميس من النصوص. وكل ما يقع بين الملف وتلك المصفوفة مسؤوليتك، فحوِّل مرة واحدة وفي مكان واحد واجعل التحويل ظاهرًا. وميزة مثل «ترتيب الإيجار» محسوبة على نصوص تضع '99' فوق '415' ولا يلاحظ أحد، لأن العمود ما زال يشبه إيجارات. والإصلاح السريع float(x or 0) يصنع صف تدريب إيجاره صفر في إعلانين من الستين: تسمية مختلَقة لا قيمة مفقودة.

Honest accountingحساب أمين

A list of dictionaries is still the right tool for ten records, for a JSON payload you will forward unchanged, or for a configuration. It is readable, it needs no import, and it is exactly what the standard library produces. It stops being right the moment you compute across rows, which is most of data analysis.

ما زالت قائمة القواميس هي الأداة الصحيحة لعشرة سجلات، أو لحمولة JSON ستمرّرها دون تغيير، أو لإعدادات. فهي مقروءة، ولا تحتاج استيرادًا، وهي بالضبط ما تنتجه المكتبة القياسية. لكنها تكفّ عن الصلاحية لحظة تحسب عبر الصفوف، وهذا معظم تحليل البيانات.

Concept 2 — NumPy: one dtype, one block, no loopsالمفهوم 2 — NumPy: نوع واحد، كتلة واحدة، بلا حلقات

The problemالمشكلة

Dividing one column by another, filtering the expensive listings, adding up a total: in a list of dictionaries each of these is a Python loop that touches one object at a time, and every number is its own boxed object scattered through memory. NumPy's answer is to store the numbers packed together in one block and to apply an operation to the whole block in a single step.

قسمة عمود على آخر، وترشيح الإعلانات الغالية، وجمع إجمالي: في قائمة القواميس يكون كل ذلك حلقة بايثون تلمس كائنًا واحدًا في كل مرة، وكل رقم كائن مستقل ومغلَّف ومبعثر في الذاكرة. أما جواب NumPy فهو أن تُخزَّن الأرقام متراصّة في كتلة واحدة وتُطبَّق العملية على الكتلة كلها في خطوة واحدة.

The ndarray: shape, ndim, dtypeالمصفوفة ndarray: الشكل والأبعاد والنوع

An ndarray (an n-dimensional array) is a fixed-size grid of values that all have the same type. That type is its dtype: float64 means every cell is an 8-byte decimal number. Its shape is the length along each axis and ndim is the number of axes: one axis for a column of rents, two for a table.

المصفوفة ndarray (مصفوفة ذات أبعاد متعددة) شبكة ثابتة الحجم من القيم كلها من النوع نفسه. وهذا النوع هو نوع البيانات (dtype): فالنوع float64 يعني أن كل خلية عدد عشري من 8 بايت. أما shape فهو الطول على كل محور، وndim عدد المحاور: محور واحد لعمود إيجارات، ومحوران لجدول.

import numpy as np

rent = np.array([415.0, 445.0, 590.0, 315.0])      # listings 1001 to 1004
print(rent)
print(rent.dtype, rent.shape, rent.ndim, rent.size)

grid = np.array([[415.0, 119.2, 4],
                 [445.0, 115.7, 3]])
print(grid.shape, grid.ndim, grid.dtype)

print(np.array(["415", "445"]).dtype)
[415. 445. 590. 315.] float64 (4,) 1 4 (2, 3) 2 float64 <U3

The last line is a quiet warning. NumPy does not parse text for you: an array of the strings "415" and "445" has dtype <U3 ("Unicode text, up to 3 characters"), and arithmetic on it will fail or, worse, concatenate.

والسطر الأخير تحذير هادئ. فـNumPy لا تحلّل النص نيابةً عنك: مصفوفة السلسلتين "415" و"445" نوعها <U3 («نص يونيكود حتى 3 أحرف»)، والحساب عليها سيفشل أو، وهو الأسوأ، سيربط النصوص.

Vectorised arithmetic and boolean masksالحساب المتجهي والأقنعة المنطقية

Vectorisation means writing one operation on whole arrays and letting compiled code run the loop for you. Comparisons vectorise too, and a comparison produces a boolean mask: an array of True and False, one per element, which you can use to select, to count, or to average.

يعني العمل المتجهي (vectorisation) أن تكتب عملية واحدة على مصفوفات كاملة وتترك لكود مترجَم أن ينفّذ الحلقة عنك. وتعمل المقارنات بالطريقة نفسها، والمقارنة تنتج قناعًا منطقيًّا (boolean mask): مصفوفة من True وFalse قيمة لكل عنصر، تستعملها للانتقاء أو للعدّ أو لأخذ متوسط.

rent = np.array([415.0, 445.0, 590.0, 315.0])

Broadcasting: two examples and two trapsالبثّ: مثالان وفخّان

What if the two arrays do not have the same shape? Broadcasting is the rule NumPy uses to combine them anyway, by stretching the smaller one along any axis where it has size 1 (or no axis at all). Example 1 multiplies a whole array by a single number. Example 2 subtracts a row of column means from a whole table, which is the first step of nearly every feature-scaling recipe.

ماذا لو لم يكن للمصفوفتين الشكل نفسه؟ البثّ (broadcasting) هو القاعدة التي تستعملها NumPy لدمجهما رغم ذلك، بمدّ الأصغر على كل محور حجمه 1 (أو لا محور له أصلًا). المثال الأول يضرب مصفوفة كاملة في عدد واحد. والمثال الثاني يطرح صفّ متوسطات الأعمدة من جدول كامل، وهي الخطوة الأولى في كل وصفة لتحجيم الخصائص تقريبًا.

import numpy as np

rent = np.array([415.0, 445.0, 590.0, 315.0])
print(rent * 1.10)                   # example 1: the scalar is stretched to every cell

X = np.array([[415.0, 119.2, 4],
              [445.0, 115.7, 3],
              [590.0, 126.7, 5],
              [315.0, 109.2, 3]])
col_mean = X.mean(axis=0)            # one mean per column
print(X.shape, col_mean.shape)
centred = X - col_mean               # example 2: (4, 3) minus (3,) gives (4, 3)
print(centred.round(2))
print(np.allclose(centred.mean(axis=0), 0))

The rule, in one sentence: line the shapes up from the right; two sizes are compatible if they are equal or if one of them is 1. Here (4, 3) against (3,) lines up as 3 with 3 and 4 with nothing, so the row of means is reused for each of the four rows. The Appendix works through the rule step by step.

One trap is loud, the other is silentأحد الفخّين صاخب والآخر صامت

Shapes (3,) and (4,) are incompatible, so NumPy raises ValueError. That is the good case. Shapes (3,) and (3, 1) are compatible: both are stretched, and you get a 3-by-3 table pairing every element with every other, with no warning. Why it is faster, with a measured numberلماذا هي أسرع، برقم مقيس

Two things make the NumPy line fast. First, the array is one contiguous block of 8-byte numbers, while a Python list is a block of pointers to separate float objects of 24 bytes each: more memory, and a trip across memory for every element. Second, the loop over the block runs in compiled code, often with the processor's wide vector instructions, instead of the interpreter executing a few bytecodes per element. Here is the same sum over a million rents, once in a Python loop and once as data.sum().

شيئان يجعلان سطر NumPy سريعًا. الأول: المصفوفة كتلة متصلة من أرقام حجم كل منها 8 بايت، أما قائمة بايثون فكتلة من المؤشرات إلى كائنات float منفصلة حجم كل منها 24 بايت: ذاكرة أكبر ورحلة عبر الذاكرة لكل عنصر. والثاني: تعمل الحلقة على الكتلة بكود مترجَم، وغالبًا بتعليمات المعالج المتجهة العريضة، بدل أن ينفّذ المفسّر بضع تعليمات وسيطة لكل عنصر. وهذا هو المجموع نفسه على مليون إيجار، مرة بحلقة بايثون ومرة بـdata.sum().

import sys
import timeit
import numpy as np

n = 1_000_000
data = np.random.default_rng(0).uniform(200, 600, n)
as_list = data.tolist()

def loop_sum(xs):
    total = 0.0
    for x in xs:
        total += x
    return total

t_loop = min(timeit.repeat(lambda: loop_sum(as_list), number=3, repeat=5)) / 3
t_numpy = min(timeit.repeat(lambda: data.sum(), number=30, repeat=5)) / 30
print(f"python loop : {t_loop * 1000:6.1f} ms")
print(f"numpy sum   : {t_numpy * 1000:6.2f} ms")
print(f"ratio       : about {t_loop / t_numpy:.0f}x")
print("array bytes :", data.nbytes)
print("list bytes  :", sys.getsizeof(as_list) + sum(sys.getsizeof(x) for x in as_list))
python loop : 88.5 ms numpy sum : 2.79 ms ratio : about 32x array bytes : 8000000 list bytes : 32000056

Read the ratio, not the millisecondsاقرأ النسبة لا الملّي ثانية

Timings depend on the machine, what else is running and the size of the data; this block is one run, and on another run or another computer the numbers will differ. What stays true is the shape of the result: tens of times faster, and about a quarter of the memory (8 MB against 32 MB here). For four numbers NumPy is not faster at all, because setting up the call costs more than the work.

تتوقف الأزمنة على الجهاز وعلى ما يعمل معه وعلى حجم البيانات؛ وهذه الكتلة تشغيل واحد، وفي تشغيل آخر أو على حاسوب آخر ستختلف الأرقام. الذي يبقى صحيحًا هو شكل النتيجة: أسرع بعشرات المرات، وبنحو ربع الذاكرة (8 ميغابايت مقابل 32 هنا). أما في أربعة أرقام فليست NumPy أسرع إطلاقًا، لأن تهيئة الاستدعاء تكلّف أكثر من العمل.

Upcasting: what happens when types mixالترقية الضمنية: ماذا يحدث حين تختلط الأنواع

An array has one dtype, so when you mix types NumPy picks one that fits everything: this is upcasting. Integers mixed with decimals become float64. Numbers mixed with text become text, with no error. Numbers mixed with None become object, which is a list in disguise: slow, and with no vector maths. Narrow types such as int8 hold only a small range, and going past it wraps around silently.

للمصفوفة نوع واحد، فعندما تخلط الأنواع تختار NumPy نوعًا يتسع للجميع: وهذه هي الترقية الضمنية (upcasting). الأعداد الصحيحة مع العشرية تصير float64. والأعداد مع النص تصير نصًّا، بلا أي خطأ. والأعداد مع None تصير object، وهي قائمة متنكّرة: بطيئة وبلا حساب متجهي. والأنواع الضيقة مثل int8 تحمل مدى صغيرًا فقط، وتجاوزه يلتف حولها بصمت.

print(np.array([1, 2.5]).dtype)
print(np.array([1, "a"]), np.array([1, "a"]).dtype)
print(np.array([1, None]), np.array([1, None]).dtype)

After this line every * or + on the array is a text operation or an error, which is why a numeric column that loaded as text is so costly.
تُبقي NumPy القيمتين وترقّي النوع إلى الوحيد الذي يحملهما: النص. لا خطأ ولا NaN. والخيار الأول يصف ما تستطيع pandas فعله حين تطلب منها ذلك بـto_numeric(errors="coerce") (المفهوم 6)؛ أما NumPy فلا تقرر من تلقاء نفسها التخلص من قيمة. وبعد هذا السطر يصير كل * أو + على المصفوفة عملية نصية أو خطأ، ولهذا يكلّف العمود الرقمي الذي حُمّل نصًّا كل هذا الثمن.

AI lensمنظور الذكاء الاصطناعي

NumPy is the lingua franca. scikit-learn turns a DataFrame into an array before it fits anything, and PyTorch's torch.from_numpy shares memory with an existing array instead of copying it. A library that wants "a matrix of features" wants an ndarray, so the dtype of your array is the dtype of your features: a text array (<U3) or an object array cannot be a feature matrix, and finding that out at fit time is late.

NumPy هي اللغة المشتركة. تحوّل scikit-learn الجدول DataFrame إلى مصفوفة قبل أن تدرّب أي شيء، وتشارك torch.from_numpy في PyTorch الذاكرةَ مع مصفوفة موجودة بدل نسخها. والمكتبة التي تريد «مصفوفة خصائص» تريد ndarray، فنوع مصفوفتك هو نوع خصائصك: المصفوفة النصية (<U3) أو مصفوفة object لا تصلح مصفوفةَ خصائص، واكتشاف ذلك عند fit متأخر.

float32 against float64. NumPy defaults to float64 (8 bytes). Deep-learning frameworks default to float32 (4 bytes): half the memory (a matrix of 1,000,000 rows by 100 columns is 800 MB as float64 and 400 MB as float32), faster on GPUs, and about seven significant digits, which is plenty for weights and pixels but not for exact whole numbers: np.float32(16_777_216) + np.float32(1) is still 16777216.0. Use float64 for accounting and analysis, float32 for training, and convert at the boundary with X.astype("float32").

float32 مقابل float64. الافتراضي في NumPy هو float64 (8 بايت). والافتراضي في أطر التعلم العميق هو float32 (4 بايت): نصف الذاكرة (مصفوفة من 1,000,000 صف في 100 عمود تساوي 800 ميغابايت بـfloat64 و400 بـfloat32)، وأسرع على وحدات المعالجة الرسومية، وبنحو سبع خانات معنوية، وهذا وفير للأوزان والبكسلات لكنه لا يكفي للأعداد الصحيحة الدقيقة: فـnp.float32(16_777_216) + np.float32(1) ما زال يساوي 16777216.0. استعمل float64 للمحاسبة والتحليل وfloat32 للتدريب، وحوّل عند الحدّ بـX.astype("float32").

Concept 3 — pandas: arrays with labelsالمفهوم 3 — pandas: مصفوفات بتسميات

The problemالمشكلة

NumPy gives speed, but a row is only a position: "the seventh number". Which listing is that? A real table also has columns of different types (a city, a rent, a date), and its row labels must stay glued to the rows when you filter or sort. pandas wraps NumPy arrays in labels, and then bundles labelled columns into a table.

تمنحك NumPy السرعة، لكن الصف عندها مجرد موضع: «الرقم السابع». فأي إعلان هذا؟ وللجدول الحقيقي أيضًا أعمدة من أنواع مختلفة (مدينة وإيجار وتاريخ)، ويجب أن تبقى تسميات صفوفه ملتصقة بالصفوف حين ترشّح أو ترتّب. وتغلّف pandas مصفوفات NumPy بتسميات، ثم تجمع الأعمدة المسمّاة في جدول.

A Series is a one-dimensional array (a single dtype) with an index: a label for each value. Here the labels are listing ids. You can reach a value by its label with .loc or by its position with .iloc, and the underlying NumPy array is always one call away with .to_numpy().

Alignment by label is the defining feature of the index. Labels "b" and "c" exist on both sides and add (12 and 23); "a" and "d" exist on one side only, so the result is missing. The category dtype stores each distinct label once, in a small table, and keeps one small integer code per row. Concept 5 — Missing values: None, NaN, NA and NaTالمفهوم 5 — القيم المفقودة: None وNaN وNA وNaT

The problemالمشكلة

An empty cell is the most ordinary thing in real data: our listings file has 2 blank rents, 4 blank areas and 1 blank room count. And Python has at least four different ways to say "nothing here". They compare differently, they live in different dtypes, and one of them silently changes the type of the column it sits in.

الخلية الفارغة أكثر الأشياء اعتيادًا في البيانات الحقيقية: ففي ملف إعلاناتنا إيجاران فارغان وأربع مساحات فارغة وعدد غرف فارغ واحد. ولدى بايثون أربع طرق على الأقل لقول «لا شيء هنا». وهي تُقارَن بصور مختلفة، وتعيش في أنواع مختلفة، وواحدة منها تغيّر بصمت نوعَ العمود الذي تجلس فيه.

Why one NaN turns integers into floatsلماذا تحوّل NaN واحدة الأعداد الصحيحة إلى عشرية

An int64 uses every one of its bit patterns for a number; there is no spare pattern that could mean "nothing here". A float64 does have one reserved: NaN (the Appendix shows it). So when pandas meets a gap in a column of whole numbers it has only one way to store it: upcast the whole column to float64.

يستعمل النوع int64 كل نمط من أنماط بتّاته لعدد؛ فلا يوجد نمط فائض يمكن أن يعني «لا شيء هنا». أما float64 فله نمط محجوز: NaN (يعرضه الملحق). فعندما تصادف pandas فجوة في عمود أعداد صحيحة لا تجد إلا طريقة واحدة لتخزينها: ترقية العمود كله إلى float64.

Nullable dtypes: gaps without changing kindالأنواع القابلة للنقص: فجوات دون تغيير الجنس

A nullable dtype (Int64, Float64, boolean, string) stores a separate mask of which cells are missing next to the data, so an integer column can have gaps and stay integer. Its missing value is pd.NA, and comparisons with it are themselves missing rather than false.

يخزّن النوع القابل للنقص (nullable dtype) (Int64 وFloat64 وboolean وstring) قناعًا منفصلًا بالخلايا المفقودة بجانب البيانات، فيمكن لعمود صحيح أن يحتوي فجوات ويبقى صحيحًا. وقيمته المفقودة هي pd.NA، والمقارنات معها مفقودة هي نفسها لا خاطئة.

import numpy as np
import pandas as pd

print((ri > 1).tolist(), (ri > 1).dtype)

The sum stays an integer (7), count reports 3 real values, and a comparison gives a boolean mask with an <NA> in it. Honest accountingحساب أمين

The nullable types are not free upgrades. They use one extra byte per value, some operations are slower, and a library that expects NumPy may convert them back to float64 or object. If your data has no gaps in a column, plain int64 is the simpler, faster choice; reach for Int64 when a gap is real and the integer-ness matters. Also, "skip the NaN" is only right when the gaps are random; if the unknown rents are the unusually high ones, every average above is biased, and no library can tell you that.

الأنواع القابلة للنقص ليست ترقيات مجانية. فهي تستعمل بايتًا إضافيًّا لكل قيمة، وبعض العمليات معها أبطأ، وقد تحوّلها مكتبة تتوقع NumPy إلى float64 أو object. فإن لم يكن في عمودك فجوات فالنوع العادي int64 أبسط وأسرع؛ ولا تلجأ إلى Int64 إلا حين تكون الفجوة حقيقية وتهمّك صحّة العدد. وكذلك فإن «تخطَّ NaN» لا يكون صحيحًا إلا إذا كانت الفجوات عشوائية؛ وإن كانت الإيجارات المجهولة هي الإيجارات المرتفعة على غير العادة فكل متوسط أعلاه منحاز، ولا تستطيع مكتبة أن تخبرك بذلك.

Concept 6 — Casting safely: strict, forgiving, and countedالمفهوم 6 — التحويل الآمن: صارم ومتسامح ومحسوب

The problemالمشكلة

Sooner or later a column arrives as text and has to become a number or a date. Python offers a strict conversion that stops at the first value it dislikes, and a forgiving one that carries on and hides the damage. The skill is choosing between them, and, whichever you choose, counting what happened.

عاجلًا أو آجلًا يصل عمود نصًّا ويجب أن يصير رقمًا أو تاريخًا. تقدّم بايثون تحويلًا صارمًا يتوقف عند أول قيمة لا تعجبه، وآخر متسامحًا يمضي ويخفي الضرر. والمهارة في الاختيار بينهما، وفي أن تعدّ ما حدث أيًّا كان اختيارك.

Treat the parse failure rate as a data-quality metric, not a detail. In the date example the guessing parser produced one wrong date (3 January for 1 March, a wrong season feature) and lost two valid dates; a training pipeline that then runs dropna() keeps one row in six, and the row it keeps is the wrong one. Honest accountingحساب أمين

Coercion is a tool, not a policy. When a column should be clean (a numeric id, a date from a system you control) the strict astype or to_datetime without coerce is better: it stops the run at the first surprise, which is cheaper than finding the surprise in a chart. Coerce-and-count earns its place when some junk is expected and you want to see it. Either way a convert-and-carry-on line with no count is the one version that is never right.

A. Why int64 has no NaN and float64 doesأ. لماذا لا يوجد NaN في int64 ويوجد في float64

An int64 is 64 bits and every one of the 264 patterns is a number, from -9,223,372,036,854,775,808 to 9,223,372,036,854,775,807: there is nothing left over to mean "missing". A float64 follows the IEEE 754 standard, in which an exponent field of all ones is reserved for infinity and for "not a number", so there are many patterns that are not numbers and one of them is the NaN pandas uses. You can look at it:

النوع int64 من 64 بتًّا وكل نمط من أنماطه الـ264 عدد، من -9,223,372,036,854,775,808 إلى 9,223,372,036,854,775,807: فلا يبقى شيء يعني «مفقود». أما float64 فيتبع معيار IEEE 754 الذي يُحجز فيه حقل الأس المملوء بالواحدات للانهاية ولـ«ليس رقمًا»، فتوجد أنماط كثيرة ليست أعدادًا وأحدها هو NaN الذي تستعمله pandas. ويمكنك أن تنظر إليه:

import numpy as np

nan = np.float64("nan")
print(hex(nan.view(np.uint64)))
print(np.iinfo(np.int64).min, np.iinfo(np.int64).max)
0x7ff8000000000000 -9223372036854775808 9223372036854775807

Nullable types sidestep the problem the other way: they keep the integers in an ordinary integer array and a second array of booleans saying which cells are missing, which is why they cost one extra byte per value.

وتتحايل الأنواع القابلة للنقص على المشكلة من الجهة الأخرى: فهي تُبقي الأعداد الصحيحة في مصفوفة صحيحة عادية، ومصفوفة ثانية من القيم المنطقية تقول أي الخلايا مفقودة، ولهذا تكلّف بايتًا إضافيًّا لكل قيمة.

B. The broadcasting rule, step by stepب. قاعدة البثّ، خطوة بخطوة

To combine two arrays: (1) write their shapes one above the other, aligned on the right; (2) pad the shorter shape on the left with 1s; (3) for each column of the two shapes the sizes must be equal or one of them must be 1; the result takes the larger size. For (4, 3) and (3,): the second becomes (1, 3), the columns give 4 against 1 and 3 against 3, so the result is (4, 3). For (3, 1) against (4,) (which becomes (1, 4)): 3 against 1 and 1 against 4, so the result is (3, 4), a table pairing every row with every column. For (3,) against (4,): 3 against 4, neither equal nor 1, so ValueError.

لدمج مصفوفتين: (1) اكتب شكليهما أحدهما فوق الآخر محاذيَين على اليمين؛ (2) املأ الشكل الأقصر من اليسار بأحاد؛ (3) في كل عمود من الشكلين يجب أن يتساوى الحجمان أو يكون أحدهما 1، وتأخذ النتيجة الحجم الأكبر. فلـ(4, 3) و(3,): يصير الثاني (1, 3)، وتعطي الأعمدة 4 مقابل 1 و3 مقابل 3، فالنتيجة (4, 3). ولـ(3, 1) مقابل (4,) (الذي يصير (1, 4)): 3 مقابل 1 و1 مقابل 4، فالنتيجة (3, 4)، جدول يقرن كل صف بكل عمود. ولـ(3,) مقابل (4,): 3 مقابل 4، لا متساويان ولا أحدهما 1، فتُرفع ValueError.

b = np.ones(3)
print((A + b).shape)
col = np.arange(3).reshape(3, 1)

print((col + row).shape)
print(col + row)
(4, 3) (3, 4) [[0 1 2 3] [1 2 3 4] [2 3 4 5]]

C. The memory arithmetic behind "a quarter"ج. حساب الذاكرة وراء «الربع»

One million float64 values in an array take 1,000,000 × 8 = 8,000,000 bytes. The same values in a Python list take a pointer each (8 bytes, 8,000,056 for the list object with its header) plus one float object each (24 bytes): 8,000,056 + 24,000,000 = 32,000,056 bytes, exactly the figure printed in Concept 2, four times the array. That ratio is a property of the layout, not of the machine, which is why it is the one number from the timing section that you should trust to reproduce.

مليون قيمة float64 في مصفوفة تشغل 1,000,000 × 8 = 8,000,000 بايت. والقيم نفسها في قائمة بايثون تشغل مؤشرًا لكل قيمة (8 بايت، أي 8,000,056 لكائن القائمة مع ترويسته) وكائن float لكل قيمة (24 بايت): 8,000,056 + 24,000,000 = 32,000,056 بايتًا، وهو بالضبط الرقم المطبوع في المفهوم 2، أي أربعة أضعاف المصفوفة. وهذه النسبة خاصية في التخطيط لا في الجهاز، ولهذا فهي الرقم الوحيد من قسم الأزمنة الذي يمكنك الوثوق بأنه سيتكرر.
