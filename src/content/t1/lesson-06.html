The problemالمشكلة

The ritual lives in a person's head and fingers. You will run it on this file, skip it on the next, and the colleague who inherits your notebook never learned it. We want the checks to run themselves, every time, in the same order, and — the part that is easy to get wrong — to tell us everything they found, not only the first thing.

الطقس يعيش في رأس شخص وأصابعه. ستشغّله على هذا الملف، وتنساه في الملف التالي، والزميل الذي يرث دفترك لم يتعلّمه قط. نريد أن تعمل الفحوص بنفسها، في كل مرة، وبالترتيب نفسه، وأن تخبرنا — وهنا يسهل الخطأ — بكل ما وجدته لا بأول شيء فقط.

def validate(df, schema):
    """Return a list of problems (an empty list means the frame matches the schema)."""
    problems = []

    def add(col, message):
        problems.append(f"{col}: {message}")

    for col in schema:
        if col not in df.columns:
            add(col, "column is missing")
    for col in df.columns:
        if col not in schema:
            add(col, "column is not in the schema")

    for col, rule in schema.items():
        if col not in df.columns:
            continue
        s = df[col]
        if str(s.dtype) != str(rule["dtype"]):
            add(col, f"dtype is {s.dtype}, expected {rule['dtype']}")
        share = s.isna().mean()
        if share > rule.get("max_missing", 0):
            add(col, f"{s.isna().sum()} missing ({share:.1%}), allowed {rule.get('max_missing', 0):.0%}")
        if rule.get("unique") and s.duplicated().any():
            add(col, f"{s.duplicated().sum()} repeated value(s)")
        if "min" in rule and (s < rule["min"]).sum() > 0:
            add(col, f"{(s < rule['min']).sum()} value(s) below {rule['min']}")
        if "max" in rule and (s > rule["max"]).sum() > 0:
            add(col, f"{(s > rule['max']).sum()} value(s) above {rule['max']}")
        if "allowed" in rule:
            bad = s.dropna()[~s.dropna().isin(rule["allowed"])]
            if len(bad) > 0:
                add(col, f"{len(bad)} value(s) outside the allowed set, e.g. {bad.iloc[0]!r}")

    if df.duplicated().sum() > 0:
        add("(whole table)", f"{df.duplicated().sum()} duplicated row(s)")
    return problems

def validate(df, schema):
    """Return a list of problems; each is a dict with a severity."""
    problems = []

    def add(col, message, level="error"):
        problems.append({"column": col, "level": level, "message": message})

    for col in schema:
        if col not in df.columns:
            add(col, "column is missing")
    for col in df.columns:
        if col not in schema:
            add(col, "column is not in the schema", level="warning")

    for col, rule in schema.items():
        if col not in df.columns:
            continue
        s = df[col]
        if str(s.dtype) != str(rule["dtype"]):
            add(col, f"dtype is {s.dtype}, expected {rule['dtype']}")
        share = s.isna().mean()
        if share > rule.get("max_missing", 0):
            add(col, f"{s.isna().sum()} missing ({share:.1%}), allowed {rule.get('max_missing', 0):.0%}",
                level="warning")
        if rule.get("unique") and s.duplicated().any():
            add(col, f"{s.duplicated().sum()} repeated value(s)")
        if "min" in rule and (s < rule["min"]).sum() > 0:
            add(col, f"{(s < rule['min']).sum()} value(s) below {rule['min']}")
        if "max" in rule and (s > rule["max"]).sum() > 0:
            add(col, f"{(s > rule['max']).sum()} value(s) above {rule['max']}")
        if "allowed" in rule:
            bad = s.dropna()[~s.dropna().isin(rule["allowed"])]
            if len(bad) > 0:
                add(col, f"{len(bad)} value(s) outside the allowed set, e.g. {bad.iloc[0]!r}")

    if df.duplicated().sum() > 0:
        add("(whole table)", f"{df.duplicated().sum()} duplicated row(s)")
    return problems


def decide(problems):
    if any(p["level"] == "error" for p in problems):
        return "STOP"
    return "GO WITH CARE" if problems else "GO"

The same failure has three more faces. Leakage: a row duplicated in the file lands on both sides of a random 80/20 split with probability 2 × 0.8 × 0.2 = 32% (appendix), so the test set holds something the model has memorised and the score is flattered. Impossible labels: if damage_level is the label, an unnoticed spelling variant is a fourth class with one example. Silent unit changes: a renamed column is caught by the block above; a column that keeps its name but switches from square metres to square feet (a factor of 10.76) is caught only by a range rule or by comparing its distribution with last month's.

Concept 3 — Five words for data qualityالمفهوم 3 — خمس كلمات لجودة البيانات

The problemالمشكلة

Your validator now has a dozen rules. Your manager asks the question managers ask: "Is the data good?" A list of twelve sentences is not an answer, and "pretty good" is not a measurement. You need a small vocabulary that groups the checks, so that you can say how the data is good or bad — and notice which kind of check you have not written yet.

The five dimensionsالأبعاد الخمسة

Data quality is not "is it perfect?" — no real file is. It is "is it fit for the use I have in mind?", and it is described along five dimensions. Each one is a plain question you can put to any table.

From words to numbersمن الكلمات إلى الأرقام

A small report turns the five words into one table a manager can read. The as_of argument matters: "how old is the newest listing?" has no answer unless you say what "today" means, and a function that reads the clock returns a different answer every time you test it.

def quality_report(df, as_of):
    dates = pd.to_datetime(df["listed_on"], format="%Y-%m-%d", errors="coerce")
    labels = df["city"].astype(str)
    rows = [
        ("completeness", "cells that are filled", f"{df.notna().mean().mean():.1%}"),
        ("completeness", "listings with an area", f"{df['area_m2'].notna().mean():.1%}"),
        ("uniqueness", "repeated listing_id", int(df["listing_id"].duplicated().sum())),
        ("uniqueness", "fully duplicated rows", int(df.duplicated().sum())),
        ("validity", "area_m2 outside 20-300", int((~df["area_m2"].dropna().between(20, 300)).sum())),
        ("consistency", "city labels, before and after strip+title",
         f"{labels.nunique()} -> {labels.str.strip().str.title().nunique()}"),
        ("consistency", "dates not written as YYYY-MM-DD", int(dates.isna().sum())),
        ("timeliness", "days since the newest listing", (pd.Timestamp(as_of) - dates.max()).days),
    ]
    return pd.DataFrame(rows, columns=["dimension", "check", "result"])

Data lineage is the record of where a table came from and what was done to it on the way: which file, fetched or exported when, loaded by which code. It is the answer to the question that always arrives, a month later: "why does this chart show a different number from last week's?"

نسب البيانات (data lineage) هو سجل مصدر الجدول وما جرى له في الطريق: أي ملف، جُلب أو صُدّر متى، وحُمّل بأي كود. وهو الجواب عن السؤال الذي يصل دائمًا بعد شهر: «لماذا يُظهر هذا الرسم رقمًا مختلفًا عن رسم الأسبوع الماضي؟».

import hashlib
import os

import pandas as pd


def lineage(path, df):
    """A small record of where a table came from, to be saved next to every result."""
    with open(path, "rb") as f:
        digest = hashlib.sha256(f.read()).hexdigest()[:12]
    return {"file": os.path.basename(path), "bytes": os.path.getsize(path),
            "sha256": digest, "rows": len(df), "columns": len(df.columns)}


path = "rental_listings_update.csv"
print(lineage(path, pd.read_csv(path)))

The fingerprint (the first 12 characters of a SHA-256 hash) changes if a single byte of the file changes, so two runs that print the same fingerprint read the same data and two that differ did not. Four habits cost almost nothing: never overwrite a raw file, put the date in its name (listings_2026-05-10.csv), save the lineage record next to every result, and keep the schema and the validation report with it. The honest cost: it is bookkeeping, and for a one-afternoon exploration a dated filename is enough.

A model is the product of a table, and a model trained on a table you cannot reproduce is a model you cannot debug. When accuracy falls in March, the first question is "did the data change or did the code?", and only a fingerprint and a validation report from January answer it in minutes. The dimensions map onto model failures one to one: completeness (a feature quietly 40% empty after a pipeline change), uniqueness (duplicates leaking between train and test), validity (a label outside its classes), consistency (a third spelling of جزئي becoming a class of its own), timeliness (a model that learned last year's rents and is asked about this year's).

import pandas as pd


def coerce(text, rule):
    """Turn a column of text into its target dtype.
    Returns (typed column, the cells that were filled in but could not be parsed)."""
    blank = text.str.strip().eq("")
    cells = text.mask(blank)                                  # blanks become <NA>
    dtype = rule["dtype"]
    if dtype in ("float64", "Int64"):
        if "thousands" in rule:
            cells = cells.str.replace(rule["thousands"], "", regex=False)
        number = pd.to_numeric(cells, errors="coerce")
        if dtype == "Int64":
            number = number.mask(number % 1 != 0)             # 3.5 rooms is not a count
        typed = number.astype(dtype)
    elif dtype == "datetime64[ns]":
        typed = pd.to_datetime(cells, format=rule["format"], errors="coerce")
    else:
        typed = cells.astype(dtype)
    failed = typed.isna() & ~blank
    return typed, text[failed]


def load_listings(path, schema=SCHEMA):
    """Load, type and validate a listings CSV. Returns (DataFrame, report)."""
    raw = pd.read_csv(path, dtype=str, keep_default_na=False, encoding="utf-8-sig")
    df = pd.DataFrame(index=raw.index)
    parse = {}
    for col in raw.columns:
        rule = schema.get(col, {"dtype": "string"})
        df[col], bad = coerce(raw[col], rule)
        parse[col] = {"blank": int(raw[col].str.strip().eq("").sum()),
                      "failed": len(bad), "example": bad.iloc[0] if len(bad) else None}

    problems = validate(df, schema)
    for col, p in parse.items():
        if p["failed"]:
            problems.append({"column": col, "level": "error",
                             "message": f"{p['failed']} cell(s) could not be parsed, e.g. {p['example']!r}"})
    return df, {"rows": len(df), "parse": parse, "problems": problems}

A machine-learning system has two doors for data: the training job reads a table to fit the model, and the serving code reads a new row to predict from it. The loader pattern belongs at both, with the same schema object. At the training door a STOP prevents fitting a model on garbage; at the serving door it prevents the quieter disaster of a confident answer about a row that would not have passed the training checks. A third use grows out of the report: store each run's counts and column means and compare them with the previous run; a rent column whose mean doubles overnight needs no range rule to be noticed. That comparison over time is drift detection, which later chapters develop.

import pandas as pd

df = pd.read_csv(
    "rental_listings.csv",
    dtype={"listing_id": "string", "city": "category", "governorate": "category",
           "rooms": "Int64", "furnished": "category", "advert": "string"},
    parse_dates=["listed_on"],
)


def check_pairs(df, a, b):
    """One problem for every value of column a that appears with more than one value of column b."""
    problems = []
    counts = df.groupby(a, observed=True)[b].nunique()
    for value, n in counts[counts > 1].items():
        problems.append(f"{a}={value!r} appears with {n} different {b} values")
    return problems

print(check_pairs(df, "city", "governorate"))

tampered = df.copy()
tampered["governorate"] = tampered["governorate"].astype(str)
tampered.loc[tampered["listing_id"] == "1009", "governorate"] = "Gaza"      # Jabalia is in North Gaza
print(check_pairs(tampered, "city", "governorate"))

The grouped count is 1 for every city in the real data, so nothing is reported. In the tampered copy Jabalia appears with two governorates and is reported once, by name. Two details: observed=True stops pandas from also listing unused categories, and the governorate column is turned into plain text first, because assigning "Gaza" into a categorical column that does not contain it would raise an error. This is a consistency rule that no single-column rule can express, which is why it is a function beside validate(), not a key in the schema.

class DataProblem(Exception):
    """The file must not be used. The message is the whole report."""


def load_or_raise(path):
    df, report = load_listings(path)
    if decide(report["problems"]) == "STOP":
        errors = [p for p in report["problems"] if p["level"] == "error"]
        lines = [f"  {p['column']}: {p['message']}" for p in errors]
        raise DataProblem(f"{path}: {len(errors)} error(s)\n" + "\n".join(lines))
    return df

Appendix — the arithmetic behind the numbers on this pageملحق — الحساب وراء أرقام هذه الصفحة

A. The enrolment means. The nine counts add up to 5,410 (842 + 0 + 1,130 + 675 + 0 + 910 + 1,265 + 0 + 588). Divided by 9 this is 601.1; divided by 6, the schools with a figure, 901.7. The difference is 300.6, which is one third of 901.7: the zeros made the typical school look a third smaller. The median of the six counted schools is the mean of the two middle values, (842 + 910) / 2 = 876.

أ. متوسطات عدد الطلبة. تجمع الأعداد التسعة 5,410 (842 + 0 + 1,130 + 675 + 0 + 910 + 1,265 + 0 + 588). وبالقسمة على 9 تعطي 601.1؛ وبالقسمة على 6، أي المدارس التي لها رقم، تعطي 901.7. والفرق 300.6، وهو ثلث 901.7: جعلت الأصفار المدرسة النموذجية تبدو أصغر بثلث. ووسيط المدارس الست المحصورة هو متوسط القيمتين الوسطيتين، (842 + 910) / 2 = 876.

B. The rent slip. The three listings typed as annual rent have true monthly rents 315, 255 and 390 (sum 960). Multiplying each by 12 adds 11 × 960 = 10,560 to the total and 10,560 / 54 = 195.6 to the mean: 334.0 + 195.6 = 529.6, the 529.5 printed above up to rounding. Three values about 12 times too large move the mean by 59% and tilt the fitted line until its slope changes sign.

ب. زلة الإيجار. الإيجارات الشهرية الحقيقية للإعلانات الثلاثة المكتوبة بوصفها سنوية هي 315 و255 و390 (مجموعها 960). ضرب كل منها في 12 يضيف 11 × 960 = 10,560 إلى المجموع و10,560 / 54 = 195.6 إلى المتوسط: 334.0 + 195.6 = 529.6، وهو الرقم 529.5 المطبوع أعلاه حتى التقريب. ثلاث قيم أكبر نحو 12 مرة مما يجب تحرّك المتوسط بنسبة 59% وتُميل الخط الملائم حتى تتغير إشارة ميله.

C. Why a duplicate leaks with probability 0.32. A random 80/20 split sends each row independently to the test set with probability 0.2. Exactly one of two copies lands there when the first is in and the second out (0.2 × 0.8) or the reverse (0.8 × 0.2): 0.16 + 0.16 = 0.32. The model is then tested on a row it saw in training.

ج. لماذا يتسرّب المكرّر باحتمال 0.32. يرسل التقسيم العشوائي 80/20 كل صف باستقلال إلى الاختبار باحتمال 0.2. وتقع نسخة واحدة بالضبط من النسختين هناك حين تكون الأولى فيه والثانية خارجه (0.2 × 0.8) أو العكس (0.8 × 0.2): 0.16 + 0.16 = 0.32. فيُختبر النموذج على صف رآه أثناء التدريب.
