Concept 1 — One tool, three jobsالمفهوم 1 — أداة واحدة وثلاث مهام

The problemالمشكلة

In Lesson 4 the manager’s question was answered in Excel. It worked, but the answer lived in cell formulas and in clicks: you removed the duplicates by hand, and next month, with a new file, you repeat every click. Power BI promises something different — record the cleaning once, model the tables, and publish a report anyone can open. It also hides things: a number can look right while the tool decided something on your behalf. This lesson is a first tour that shows both the promise and the places where it quietly goes wrong.

في الدرس 4 أُجيب عن سؤال المدير في Excel. نجح ذلك، لكن الجواب عاش في صيغ الخلايا وفي النقرات: حذفت المكرَّرات يدويًّا، وفي الشهر القادم مع ملف جديد تعيد كل نقرة. يعد Power BI بشيء مختلف — سجّل التنظيف مرة واحدة، وانمذج الجداول، وانشر تقريرًا يفتحه أي شخص. لكنه يخفي أشياء أيضًا: قد يبدو الرقم صحيحًا بينما قررت الأداة شيئًا نيابةً عنك. هذا الدرس جولة أولى تُظهر الوعد ومواضع الخطأ الصامت معًا.

Desktop, Service and Mobile: three products, one nameDesktop وService وMobile: ثلاثة منتجات باسم واحد

“Power BI” is a family. Power BI Desktop is the Windows application where you build: connect to data, clean it, model it and draw the report. It saves one file, a .pbix. Power BI Service is the website, hosted by Microsoft, where a published report lives so that other people can open it, where you schedule a refresh and share. Power BI Mobile is the phone app that displays published reports. You build in Desktop; you only ever read in the other two.

The three jobs, and where each livesالمهام الثلاث وأين تقع كل واحدة

Everything you do in Desktop is one of three jobs, and they run in a fixed order, like a pipeline. Connect and transform happens in the Power Query Editor (Home → Transform data): you pick a source and record the steps that clean it. Model happens in Model view and in the formula bar: you relate tables and write DAX formulas. Visualise happens in Report view: you drag fields onto a canvas and get charts. The three icons on the left edge of the window switch between Report, Table and Model views (newer versions add more; names vary slightly by version).

كل ما تفعله في Desktop واحدة من ثلاث مهام، وتجري بترتيب ثابت كخط معالجة. الاتصال والتحويل يتمان في محرر Power Query (Home ← Transform data): تختار المصدر وتسجّل الخطوات التي تنظّفه. والنمذجة في عرض النموذج (Model view) وشريط الصيغة: تربط الجداول وتكتب صيغ DAX. والتصوير في عرض التقرير (Report view): تسحب الحقول إلى لوحة فتحصل على مخططات. وتبدّل الأيقونات الثلاث على الحافة اليسرى بين عرض التقرير وعرض الجدول وعرض النموذج (تضيف الإصدارات الأحدث غيرها؛ وتختلف الأسماء قليلًا بين الإصدارات).

Honesty box — when the simpler thing winsصندوق الصدق — متى يفوز الأبسط

For a one-off question on one small file, a PivotTable is faster than a Power BI project, and for anything that needs a statistical test or a model, a notebook wins. Power BI earns its keep when the same cleaning must be repeated every month and the result must be an interactive page that non-programmers can use.

AI lensمنظور الذكاء الاصطناعي

A list of Power Query steps is a small, auditable data-prep pipeline — the same idea as a scikit-learn Pipeline: named stages, each taking the output of the one before, re-runnable on new data. That is exactly why it matters for AI. A model trained on a month with one Shawarma Wrap at 120.0 instead of 12.0 learns that typo as data, and the people who inherit the model need the step list to know what happened to the rows before training. BI answers what happened; a model predicts what will — and only the first is trustworthy if the cleaning is written down.

قائمة خطوات Power Query هي خط معالجة بيانات صغير قابل للتدقيق — الفكرة نفسها في Pipeline بمكتبة scikit-learn: مراحل مسمّاة تأخذ كل واحدة ناتج التي قبلها ويمكن إعادة تشغيلها على بيانات جديدة. ولهذا بالضبط يهم الأمر للذكاء الاصطناعي. فالنموذج المدرَّب على شهر فيه شاورما واحدة بسعر 120.0 بدل 12.0 يتعلم ذلك الخطأ المطبعي على أنه بيانات، ومن يرث النموذج يحتاج قائمة الخطوات ليعرف ما جرى للصفوف قبل التدريب. يجيب ذكاء الأعمال عن ما حدث، ويتنبأ النموذج بـ ما سيحدث — ولا يوثَق إلا بالأول حين يكون التنظيف مكتوبًا.

Concept 2 — Get data: connect first, decide laterالمفهوم 2 — Get data: اتصل أولًا وقرّر لاحقًا

The problemالمشكلة

In Excel you double-click the CSV and it opens, already in a grid. In Power BI you click Get data, and a window offers a green-looking button called Load. One click later the Fields pane lists eight columns, the table says 771 rows, and it feels finished. It is not: the tool has already made decisions for you — which column is a number, which is text, which is a date — and none of them was shown to you.

في Excel تنقر مرتين على ملف CSV فيُفتح في شبكة جاهزة. وفي Power BI تنقر Get data فتعرض نافذة زرًّا اسمه Load. بعد نقرة واحدة تسرد لوحة الحقول ثمانية أعمدة ويقول الجدول 771 صفًّا، ويبدو كل شيء منتهيًا. وهو ليس كذلك: فقد اتخذت الأداة قرارات نيابةً عنك — أي عمود رقم وأي عمود نص وأي عمود تاريخ — ولم يُعرض عليك أي منها.

Locale: when a dot is not a decimal pointاللغة الإقليمية: حين لا تكون النقطة فاصلة عشرية

Converting text to a number depends on a locale: which character is the decimal mark and which is the thousands separator. If you use Transform → Data Type → Using Locale… you choose both the type (Decimal Number) and the locale (English (United States)); the editor records it as a culture name in the step, "en-US". The file uses a dot for decimals (12.0, 3.5). On a computer set to a locale that uses a decimal comma, a plain conversion can read that dot as a thousands separator, so 12.0 may become 120 and 3.5 become 35. In pandas the same mistake is read_csv(…, thousands=".", decimal=","): we ran it, and every price in the file comes out ten times larger. It is a known symptom, and it is silent. The cure is to say the locale explicitly, in the recorded step, so that the answer does not depend on whose computer opens the file.

يعتمد تحويل النص إلى عدد على لغة إقليمية (locale): أي محرف هو الفاصلة العشرية وأيّ محرف هو فاصل الآلاف. وإذا استعملت Transform ← Data Type ← Using Locale… اخترت النوع (Decimal Number) واللغة الإقليمية (English (United States)) معًا؛ ويسجّله المحرر اسم ثقافة في الخطوة هو "en-US". يستعمل الملف النقطة للكسور العشرية (12.0 و3.5). وفي حاسوب مضبوط على لغة إقليمية تستعمل الفاصلة العشرية قد يقرأ التحويل العادي تلك النقطة فاصلَ آلاف، فيصبح 12.0 العدد 120 و3.5 العدد 35. وفي pandas الخطأ نفسه هو read_csv(…, thousands=".", decimal=","): جرّبناه فخرج كل سعر في الملف أكبر بعشر مرات. عَرَض معروف وصامت. والعلاج أن تذكر اللغة الإقليمية صراحةً في الخطوة المسجّلة، فلا يتوقف الجواب على حاسوب من يفتح الملف.

This is the Power BI face of the same trap you met in Theory Lesson 4 (decimal=, thousands=, encoding= in read_csv): a file is only half of the story; the reader’s settings are the other half.

وهذا وجه Power BI للفخ الذي صادفته في الدرس 4 النظري (المعاملات decimal= وthousands= وencoding= في read_csv): الملف نصف الحكاية فقط، ونصفها الآخر إعدادات من يقرؤه.

AI lensمنظور الذكاء الاصطناعي

Type detection is the Power BI twin of the dtype guess in pd.read_csv, and both fail quietly, in different ways: pandas treats the text n/a as missing by default, so unit_price arrives as float64 with one NaN and no message, whereas Power Query keeps the cell as text or turns it into an Error. Now suppose unit_price stays text and the table goes to a model: an encoder will treat "12.0" and "12" as two different categories and turn a numeric feature into dozens of one-hot columns, with no error anywhere. The same goes for the locale slip: a price feature ten times too large changes every coefficient. Check the types of the columns you will feed a model before you look at accuracy.

الكشف عن الأنواع هو توأم Power BI لتخمين dtype في pd.read_csv، وكلاهما يفشل بهدوء بطريقتين مختلفتين: يعامل pandas النص n/a قيمة مفقودة افتراضيًّا، فيصل unit_price بنوع float64 مع NaN واحدة دون أي رسالة، بينما تُبقي Power Query الخلية نصًّا أو تحوّلها إلى خطأ (Error). والآن افترض أن unit_price بقي نصًّا وذهب الجدول إلى نموذج: سيعامل المرمِّز "12.0" و"12" فئتين مختلفتين ويحوّل ميزة رقمية إلى عشرات أعمدة one-hot، دون خطأ في أي مكان. وكذلك زلة اللغة الإقليمية: ميزة سعر أكبر عشر مرات تغيّر كل المعاملات. افحص أنواع الأعمدة التي ستغذي بها نموذجًا قبل أن تنظر إلى الدقة.

Here is the idea to hold on to. Every command you click — promote the header, change a type, remove duplicates — is recorded as one entry in Applied Steps, and each entry is a line of code in a language called M. Click an older step and the grid shows the table as it was then; the steps after it are not undone, so you can inspect any moment of the pipeline. وهذه هي الفكرة التي يجب التمسك بها. كل أمر تنقر عليه — ترقية العناوين أو تغيير نوع أو حذف المكرَّرات — يُسجَّل مدخلًا واحدًا في الخطوات المطبَّقة (Applied Steps)، وكل مدخل سطر شيفرة بلغة اسمها M. انقر خطوة أقدم فتعرض الشبكة الجدول كما كان حينها؛ ولا تُلغى الخطوات التي بعدها، فيمكنك فحص أي لحظة من خط المعالجة. احذف خطوة بالعلامة × بجانبها فيستمر الخط بدونها. ولا يتعدل ملف المصدر أبدًا: فالخطوات تصف كيف يُقرأ. قارن ذلك بـ Remove Duplicates في Excel الذي يحذف الصفوف من النسخة الوحيدة التي تملكها.

Query folding, in one honest paragraphطيّ الاستعلام (Query Folding) في فقرة صادقة

When the source is a database, Power Query can often translate your steps — filter rows, remove columns, group — into one SQL statement and let the database do the work, so that only the answer travels to your PC; that is query folding. In the editor you can right-click a step and see whether View Native Query is available: if it is greyed out, that step did not fold, and (depending on the connector) neither will most steps after it. A CSV or Excel file has no engine to hand work to, so nothing folds here: Power Query reads the whole file and runs every step itself, in memory, on your machine. That is perfectly fine for 771 lines and painful for 50 million; you will meet it again when the source is SQL.

حين يكون المصدر قاعدة بيانات تستطيع Power Query غالبًا ترجمة خطواتك — ترشيح الصفوف وإزالة الأعمدة والتجميع — إلى عبارة SQL واحدة وتدع قاعدة البيانات تعمل، فلا يسافر إلى حاسوبك إلا الجواب؛ وهذا هو طيّ الاستعلام (Query Folding). وفي المحرر يمكنك النقر بالزر الأيمن على خطوة لترى هل View Native Query متاح: فإن كان رماديًّا فهذه الخطوة لم تُطوَ، و(بحسب الموصِّل) غالبًا لن تُطوى معظم الخطوات بعدها. أما ملف CSV أو Excel فلا محرك فيه تسلَّم إليه العمل، فلا يُطوى شيء هنا: تقرأ Power Query الملف كله وتنفذ كل خطوة بنفسها في الذاكرة على جهازك. وهذا مقبول تمامًا لـ 771 سطرًا ومؤلم لـ 50 مليونًا؛ وستلقاه ثانية حين يكون المصدر SQL.

AI lensمنظور الذكاء الاصطناعي

Power Query’s steps map onto scikit-learn’s idea: a pipeline of named stages that you can print, review and re-run. There is one trap the two share, leakage. Steps that depend only on the row itself (trim, set a type, remove an identical row) are safe to run over the whole table. Steps that learn something from the data — “replace the missing price with the column average” (6.52 here), “drop prices above three standard deviations”, “scale to 0–1” — use every row, including rows that a model should only meet later. If you will test a model on October, a statistic computed on September and October has already looked at the answer. Our own < 50 was picked after seeing the whole month, which is why Version 3 says out loud that it is hand-picked.

What a star schema is, in two paragraphsما المخطط النجمي، في فقرتين

A star schema sorts tables into two kinds. A fact table records events, one row per thing that happened — here Orders, one row per order line, with the numbers you add up (qty, unit_price, line_total). A dimension table describes the things the events refer to — here Menu (item, category, list price), and soon a calendar of dates or a table of customer types. The fact table sits in the middle with a many-to-one relationship to each dimension, so the picture is a star; filters start at a dimension and flow to the fact table, never between dimensions.

يصنّف المخطط النجمي (Star Schema) الجداول نوعين. جدول الحقائق (Fact table) يسجّل الأحداث، صفًّا لكل ما حدث — وهو هنا Orders، صف لكل سطر طلب، ومعه الأعداد التي تُجمع (qty وunit_price وline_total). وجدول الأبعاد (Dimension table) يصف الأشياء التي تشير إليها الأحداث — وهو هنا Menu (الصنف والفئة وسعر القائمة)، وقريبًا تقويم للتواريخ أو جدول لأنواع العملاء. يجلس جدول الحقائق في الوسط بعلاقة متعدد إلى واحد مع كل بُعد، فيكون الشكل نجمة؛ وتبدأ المرشِّحات من بُعد وتجري إلى جدول الحقائق، لا بين الأبعاد.

Why bother, when the CSV already has everything in one flat table? Because each descriptive fact then lives in one place (a category is fixed in Menu, not in 748 rows that may drift apart), the dimension tables are small and fast to filter, and the same dimension serves several fact tables later (orders, stock, wastage). The flat table is not wrong — it is simply the right size for one question on one file.

ولماذا هذا العناء ما دام ملف CSV يحوي كل شيء في جدول مسطّح واحد؟ لأن كل معلومة وصفية تعيش حينئذ في مكان واحد (فئة الصنف مثبتة في Menu لا في 748 صفًّا قد تتباعد)، ولأن جداول الأبعاد صغيرة وسريعة الترشيح، ولأن البُعد نفسه يخدم لاحقًا عدة جداول حقائق (الطلبات والمخزون والهدر). والجدول المسطّح ليس خاطئًا — إنه فقط بالحجم المناسب لسؤال واحد على ملف واحد.

Honesty box — a star is not always worth itصندوق الصدق — النجمة لا تستحق دائمًا

With one flat file and one question, a relationship adds a table, a line and a place to make a mistake. Our cafeteria is a star with one point; the date dimension arrives when time analysis does.

A dashboard shows what happened; a model predicts what will. The two meet after deployment: the best place to watch a model is a Power BI page. The problemالمشكلة

There are three ways to get 8,062.00 on a card: drag line_total and let Power BI sum it; add a column that multiplies quantity by price and sum that; or write a formula that does the multiplication and the sum together. Today all three agree. They stop agreeing the day somebody changes the summary to Average, asks for revenue per order, or wants the same total inside another formula — and nothing warns you that you chose the weakest of the three.

ما الذي تغيّر. ينتقل الضرب إلى SUMX التي تقيّم qty * unit_price صفًّا صفًّا وتجمع النتائج، داخل مقياس له اسم. ما الذي يصلحه. 8,062.00 نفسها، لكن التعريف مكتوب ولا تحوّله نقرة إلى Average؛ ولا شيء يُخزَّن؛ ويمكن حذف العمود. ما الذي ما زال ناقصًا. يجيب عن «كم؟» فقط. و«كم لكل طلب؟» يحتاج عدّ الطلبات، ومن لا يملك عدًّا سيمدّ يده إلى Average لـ line_total — 10.78 — ويبلّغ عنه حجمَ السلة.

Total Revenue = SUMX(Orders, Orders[qty] * Orders[unit_price])
Orders Count = DISTINCTCOUNT(Orders[order_id])
Revenue per Order = DIVIDE([Total Revenue], [Orders Count])

// Three cards, no filter          ->  8,062.00 | 611 | 13.19
// The Falafel Sandwich bar        ->    917.00 |  84 | 10.92
// Staff selected in a slicer      ->  1,716.50 | 154 | 11.15

What changed. Two more measures: DISTINCTCOUNT counts different order_id values (611 orders, not 748 lines), and DIVIDE reuses the other two by name. What it fixes. Revenue per order is 13.19, correct in every context: 10.92 for the Falafel Sandwich bar, 11.15 for Staff. DIVIDE returns a blank instead of an error or Infinity when an order count is zero, so an empty slice shows nothing rather than nonsense. What is still imperfect. Distinct counts do not add up: orders by customer type are 448 + 154 + 75 = 677, not 611, because in this file 66 orders contain lines with different customer_type values. A measure is exact about its context; whether the data model agrees with the business (can one order have two customer types?) is a question for the cafeteria manager.

ما الذي تغيّر. مقياسان آخران: DISTINCTCOUNT تعدّ قيم order_id المختلفة (611 طلبًا لا 748 سطرًا)، وDIVIDE تعيد استعمال المقياسين الآخرين بالاسم. ما الذي يصلحه. الإيراد لكل طلب 13.19، صحيح في كل سياق: 10.92 لعمود Falafel Sandwich و11.15 لـ Staff. وتُرجع DIVIDE فراغًا بدل خطأ أو Infinity حين يكون عدد الطلبات صفرًا، فتعرض الشريحة الفارغة لا شيء بدل هراء. ما الذي ما زال ناقصًا. الأعداد المميزة لا تُجمع: طلبات أنواع العملاء 448 + 154 + 75 = 677 لا 611، لأن في هذا الملف 66 طلبًا فيها أسطر بقيم customer_type مختلفة. والمقياس دقيق في سياقه؛ أما هل يتفق نموذج البيانات مع العمل (هل يجوز أن يكون للطلب الواحد نوعا عميل؟) فسؤال لمدير الكافتيريا.

A calculated column is feature engineering: a new value stored on each row, which a model can later read as an input. A measure is an evaluation metric: a number computed over whatever slice you ask about. The distinction guards against two failures. Leakage by construction: if the label is revenue and you add line_total = qty * unit_price as a feature, the model predicts revenue from revenue and scores a perfect, useless R² = 1. Averages that hide failures: a model’s accuracy as one number can look fine while the slice for Visitors (75 of 611 orders) fails; a measure on a slicer or a matrix by customer_type shows the slice. Model evaluation by slice is a Power BI skill.

العمود المحسوب هو هندسة الميزات: قيمة جديدة مخزنة على كل صف، يستطيع نموذج أن يقرأها لاحقًا مُدخَلًا. والمقياس مقياس تقييم: رقم يُحسب على أي شريحة تسأل عنها. والتمييز بينهما يحمي من فشلين. التسرّب بالبناء: إن كانت التسمية (label) هي الإيراد وأضفت line_total = qty * unit_price ميزةً، فإن النموذج يتنبأ بالإيراد من الإيراد ويسجّل R² = 1 مثاليًّا وعديم الفائدة. ومتوسطات تخفي الفشل: قد تبدو دقة النموذج رقمًا واحدًا سليمًا بينما تفشل شريحة الزوار (75 من 611 طلبًا)؛ ومقياس على مقطِّع أو مصفوفة حسب customer_type يُظهر الشريحة. وتقييم النموذج حسب الشرائح مهارة Power BI.

What is inside a .pbixماذا يوجد داخل ملف pbix

File → Save as writes one .pbix file. Inside are the report pages, the data model, the queries with their Applied Steps and — because a CSV or Excel source is always imported — a compressed copy of the data itself. Three consequences. The file is self-contained: it opens offline and the visuals work without the CSV. It contains the data: do not email a file with real student or customer records to people who may not see them. And to share the structure without the data, File → Export → Power BI template writes a .pbit that holds the report, model and queries but no rows. (Databases can also be connected in DirectQuery mode, which asks the source at view time instead of importing; flat files cannot. Newer versions can also save a Power BI project, a folder of text files that works with Git — check your version.)

يكتب File ← Save as ملف .pbix واحدًا. وفي داخله صفحات التقرير ونموذج البيانات والاستعلامات مع خطواتها المطبَّقة و— لأن مصدر CSV أو Excel يُستورَد دائمًا — نسخة مضغوطة من البيانات نفسها. ثلاث نتائج. الملف قائم بذاته: يُفتح دون اتصال وتعمل العناصر المرئية دون ملف CSV. ويحتوي البيانات: فلا ترسل ملفًّا فيه سجلات حقيقية لطلاب أو عملاء إلى من لا يحق لهم رؤيتها. ولمشاركة البنية دون البيانات يكتب File ← Export ← Power BI template ملف .pbit يحمل التقرير والنموذج والاستعلامات دون صفوف. (ويمكن وصل قواعد البيانات بوضع DirectQuery الذي يسأل المصدر وقت العرض بدل الاستيراد؛ أما الملفات المسطّحة فلا. وتستطيع الإصدارات الأحدث حفظ مشروع Power BI، وهو مجلد ملفات نصية يعمل مع Git — تحقق من إصدارك.)

Refresh, data-source paths and privacy levelsالتحديث ومسارات المصادر ومستويات الخصوصية

Home → Refresh re-runs every query: it reads the source files again, replays the Applied Steps on whatever is in them, and reloads the model. Nothing else happens — in particular, no new cleaning rule appears (Concept 7). The query remembers where its source is. When the path is wrong, three places fix it:

يعيد Home ← Refresh تشغيل كل استعلام: يقرأ ملفات المصدر مرة أخرى، ويعيد تشغيل الخطوات المطبَّقة على ما فيها، ويعيد تحميل النموذج. ولا شيء آخر يحدث — وخصوصًا لا تظهر قاعدة تنظيف جديدة (المفهوم 7). والاستعلام يتذكر أين مصدره. فإذا كان المسار خطأً أصلحه أحد ثلاثة مواضع:

  • The parameter (best): Home → Transform data → Edit parameters, and type the folder where this computer keeps the CSV files. One value, both queries (Orders and Menu) follow it.المعامل (الأفضل): Home ← Transform data ← Edit parameters، واكتب المجلد الذي يحفظ فيه هذا الحاسوب ملفات CSV. قيمة واحدة تتبعها الاستعلامان (Orders وMenu).
  • Data source settings: File → Options and settings → Data source settings lists every source the file uses; Change Source… rewrites a path, and Edit Permissions… shows credentials and the privacy level.Data source settings: يسرد File ← Options and settings ← Data source settings كل مصدر يستعمله الملف؛ ويعيد Change Source… كتابة مسار، ويعرض Edit Permissions… بيانات الاعتماد ومستوى الخصوصية.
  • The Source step itself: select it in Applied Steps and edit the code (the worst option, which is why Version 3 used a parameter).خطوة Source نفسها: حدّدها في Applied Steps وعدّل الشيفرة (أسوأ الخيارات، ولهذا استعملت النسخة 3 معاملًا).

Privacy levels are Power Query’s guard against leaking data between sources. Each source is marked Public, Organizational or Private, and when one query combines two sources Power Query refuses to send rows from a more private source to a less private one. The first time you merge or reference queries on different files it may stop with “Information is required about data privacy” (the wording varies by version). For your own local files, Private is the safe answer. Choosing Ignore Privacy Levels silences the prompt and also removes the guard; do it only when you know what each source contains.

مستويات الخصوصية حارس Power Query ضد تسرّب البيانات بين المصادر. يُعلَّم كل مصدر Public أو Organizational أو Private، وحين يجمع استعلام واحد مصدرين ترفض Power Query إرسال صفوف من مصدر أكثر خصوصية إلى مصدر أقل خصوصية. وأول مرة تدمج أو تشير إلى استعلامات على ملفات مختلفة قد تتوقف برسالة «Information is required about data privacy» (وتختلف الصياغة بين الإصدارات). ولملفاتك المحلية الإجابة الآمنة Private. واختيار Ignore Privacy Levels يُسكت الرسالة ويزيل الحارس أيضًا؛ افعله فقط حين تعرف ما يحويه كل مصدر.

Publishing, and the ways out that need no accountالنشر وطرق الخروج التي لا تحتاج حسابًا

Publishing is the one step in this lesson that needs an account, normally a work or school one. Home → Publish asks you to sign in, lets you pick a workspace, and uploads the report and its model to the Power BI Service. Other people then open it in a browser or the mobile app; sharing usually needs licences on the readers’ side or a capacity on the owner’s (rules vary by organisation, so ask your university). A scheduled refresh of a file that sits on your own disk needs an on-premises data gateway, a small program on a computer that can see the file, because the Service cannot reach into your C: drive. Files in OneDrive or SharePoint, or cloud databases, need no gateway.

النشر هو الخطوة الوحيدة في هذا الدرس التي تحتاج حسابًا، وهو عادةً حساب عمل أو مدرسة. يطلب منك Home ← Publish تسجيل الدخول، ويتيح لك اختيار مساحة عمل، ويرفع التقرير ونموذجه إلى خدمة Power BI. ثم يفتحه الآخرون في متصفح أو تطبيق الجوال؛ والمشاركة تحتاج عادةً تراخيص لدى القرّاء أو سعة لدى المالك (تختلف القواعد بين المؤسسات فاسأل جامعتك). والتحديث المجدول لملف على قرصك يحتاج بوابة بيانات محلية (on-premises data gateway)، وهي برنامج صغير على حاسوب يرى الملف، لأن الخدمة لا تستطيع الوصول إلى قرص C: عندك. أما الملفات في OneDrive أو SharePoint أو قواعد البيانات السحابية فلا تحتاج بوابة.

If you have no account, you lose nothing that the exercises need. A saved .pbix is a finished deliverable that anyone with Power BI Desktop can open and refresh. Other ways to hand the answer over:

AI features inside Power BI, and dashboards that watch modelsميزات الذكاء الاصطناعي داخل Power BI ولوحات تراقب النماذج

Power BI ships several AI-flavoured features. They are optional, they depend on your version, region and licence, and you should not count on any of them being available to you: the Q&A visual (type a question, get a chart; it works only as well as your table and column names), Copilot (a generative assistant that can suggest visuals and DAX; it needs a paid capacity and an administrator to enable it), the Key influencers and Decomposition tree visuals (which fields go with a higher or lower value of a metric), and, in the Analytics pane of a line chart, Find anomalies and Forecast. Treat every output as a hypothesis to check against the totals you already trust. With 22 trading days of data, a forecast or anomaly detector has very little to learn from, and Key influencers shows association, not cause.

يأتي Power BI بعدة ميزات بنكهة الذكاء الاصطناعي. وهي اختيارية، وتعتمد على إصدارك ومنطقتك وترخيصك، ولا يجوز أن تعوّل على توفر أيٍّ منها لك: عنصر Q&A المرئي (اكتب سؤالًا تحصل على مخطط؛ وهو لا يجيد إلا بقدر جودة أسماء جداولك وأعمدتك)، وCopilot (مساعد توليدي يقترح عناصر مرئية وDAX؛ ويحتاج سعة مدفوعة ومسؤولًا يفعّله)، وعنصرا Key influencers وDecomposition tree (أي الحقول تصاحب قيمة أعلى أو أدنى لمقياس)، وفي لوحة Analytics لمخطط خطي Find anomalies وForecast. واعتبر كل مخرَج فرضية تُفحص مقابل الإجماليات التي تثق بها. ومع 22 يوم عمل من البيانات لا يجد التنبؤ ولا كاشف الشذوذ ما يتعلمان منه إلا قليلًا، ويُظهر Key influencers ارتباطًا لا سببًا.

Honesty box — what to take from this tourصندوق الصدق — ما تأخذه من هذه الجولة

Power BI Desktop is an excellent way to make a cleaning recipe repeatable and an interactive page shareable, and a poor place to do statistics or to hide a bad assumption. Everything it did in this lesson — 771 lines to 748, 8,062.00, the same top three, the same busiest hour — Python and Excel did too. What it adds is the recorded steps, the model that lets a slicer reach the right rows, and a page a non-programmer can use. What it costs: Windows, a licence for sharing, and a habit of checking that its defaults mean what you think.

Power BI Desktop طريقة ممتازة لجعل وصفة التنظيف قابلة للتكرار وصفحة تفاعلية قابلة للمشاركة، ومكان رديء لإجراء الإحصاء أو لإخفاء افتراض سيئ. وكل ما فعله في هذا الدرس — 771 سطرًا إلى 748 و8,062.00 والأصناف الثلاثة الأولى نفسها وساعة الذروة نفسها — فعله Python وExcel أيضًا. وما يضيفه هو الخطوات المسجّلة والنموذج الذي يجعل المقطِّع يصل إلى الصفوف الصحيحة وصفحة يستعملها غير المبرمج. وثمنه: ويندوز وترخيص للمشاركة وعادة التحقق من أن افتراضاته تعني ما تظنه.

AI lensمنظور الذكاء الاصطناعي

The cleaning recipe is one half of a model’s feature pipeline; the dashboard is the other half, the part that tells you whether the pipeline still works. A model trained on September’s cleaned 748 lines and later fed October’s uncleaned lines suffers training–serving skew: it never saw an n/a price or a trailing-space Latte. Keeping the Applied Steps next to the model’s documentation, and putting row-count, null-count and drift measures on a monitoring page, is how a team notices — before the customers do.

وصفة التنظيف نصف خط ميزات النموذج؛ ولوحة المعلومات هي النصف الآخر، الذي يخبرك هل ما زال الخط يعمل. فنموذج دُرّب على الأسطر الـ 748 المنظَّفة في سبتمبر ثم غُذّي بأسطر أكتوبر غير المنظَّفة يعاني انحراف التدريب عن الخدمة (training–serving skew): لم يرَ قط سعر n/a ولا Latte بمسافة في آخرها. وحفظ الخطوات المطبَّقة بجانب وثائق النموذج ووضع مقاييس عدد الصفوف وعدد الفراغات والانجراف في صفحة مراقبة هو ما يجعل الفريق يلاحظ — قبل أن يلاحظ الزبائن.

  • Choose Transform Data, not Load, for a file you did not make; type detection is a draft made from a sample.اختر Transform Data لا Load لملف لم تصنعه؛ فكشف النوع مسودة من عيّنة.
  • Applied Steps are a recorded, readable recipe in M. The mistakes cheat-sheetورقة الأخطاء الشائعة

  • Clicking Load and building visuals on unseen types. → Transform Data first; check the type icons.نقر Load وبناء عناصر مرئية على أنواع لم تُرَ. ← Transform Data أولًا وافحص أيقونات الأنواع.
  • Adding an Index column before Remove Duplicates (+175.00 of duplicates stay). → Duplicates first.إضافة عمود Index قبل Remove Duplicates (تبقى 175.00 من المكرَّرات). ← المكرَّرات أولًا.
  • Removing duplicates with one column selected (610 lines, 6,598.50). → Select all columns.حذف المكرَّرات مع تحديد عمود واحد (610 أسطر و6,598.50). ← حدّد كل الأعمدة.
  • Cleaning the key on one side of a join only. → The same steps on both; re-run the Left Anti check.تنظيف المفتاح في جهة واحدة من الربط. ← الخطوات نفسها على الجهتين وأعد فحص Left Anti.
  • Leaving “Sum of order_id” in a table. → Don’t summarize, or text.ترك «Sum of order_id» في جدول. ← Don’t summarize أو نص.
  • Dragging a numeric field instead of writing a measure. → One named measure per number.سحب حقل عددي بدل كتابة مقياس. ← مقياس مسمّى لكل رقم.
  • Putting the hierarchy on a line chart’s axis. → Pick the date field itself.وضع التسلسل الهرمي على محور مخطط خطي. ← اختر حقل التاريخ نفسه.
  • Typing a file path into a query, forgetting Close & Apply, trusting Refresh to clean. → A parameter, the banner, the three reconciliations.كتابة مسار ملف في استعلام، ونسيان Close & Apply، والوثوق بأن التحديث ينظّف. ← معامل، والشريط، والمطابقات الثلاث.

# Read every column as text first, as Power Query does. (By default pandas would
# silently turn the text 'n/a' into NaN and load unit_price as float64.)
raw = pd.read_csv(D + "cafeteria_orders.csv", dtype=str, keep_default_na=False)
menu = pd.read_csv(D + "cafeteria_menu.csv")

def typed(df):                                   # Promoted + Typed + NoErrors
    t = df.copy()
    t["order_id"] = t["order_id"].astype(int)
    t["order_time"] = pd.to_datetime(t["order_time"])
    t["qty"] = t["qty"].astype(int)
    t["unit_price"] = pd.to_numeric(t["unit_price"], errors="coerce")   # 'n/a' -> NaN
    return t

def valid(t):                                    # the Valid step
    return t[(t.qty > 0) & t.unit_price.notna() & (t.unit_price < 50)]

def revenue(t):
    return (t.qty * t.unit_price).sum()

t["item"] = t["item"].str.strip().str.title()    # Tidy
u = t.drop_duplicates()                          # Unique
